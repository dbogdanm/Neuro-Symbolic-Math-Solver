# Superseded figures

These four charts were produced by hand during earlier development. They are
kept for provenance but are **not cited in the paper or the README**, for
reasons that would not survive review:

| File | Problem |
|---|---|
| `Chart1.png` | GSM8K "top 20": reports the pipeline at **95%** (19/20). |
| `Chart3.png` | GSM8K "top 21": reports the same system at **100%** (21/21), and DeepSeek 14B at 76.2% where `Chart1` reports 80%. Adding one problem cannot turn 19/20 into 21/21 — the two figures come from different runs presented as one result. |
| `Chart2.png` | MATH500 "top 31": an arbitrary cut of the benchmark, with no recorded run behind it. |
| `Chart_v3_vs_v2_SVAMP.png` | SVAMP at 87.5% — that is 7/8 or 14/16 problems out of the 300 in `tests/svamp.json`. No results file was kept, and no generator script was committed, so the number cannot be reproduced or checked. |

Shared problems across all four: sample sizes of 8–31 with no confidence
intervals (on n=20, the gap between 80% and 95% is three problems, p≈0.34 by
Fisher's exact test); cut points chosen after the fact; no generator script, so
the figures cannot be regenerated; and inconsistent colour encoding between
them — green means "our pipeline" in `Chart1` but "Gemini" in `Chart3`. The
y-axis label reads "precision accuracy", conflating two distinct metrics; the
quantity plotted is accuracy.

## What replaced them

`tests/results/overnight_results.jsonl` — a complete, resumable run over 130
problems (GSM8K 50, MATH500 50, AIME 2025 30) with the model's raw answer
recorded for every one, so any figure drawn from it can be re-checked and
re-graded. The current figures in `Charts/` are all generated by scripts in
`utils/`.

## To restore the external baselines

The DeepSeek-14B and Gemini-2.5-Flash comparisons are worth having; they just
need a recorded run. Extend `BENCHMARKS` in `tests/overnight_bench.py` and pass
the model as an argument:

    python tests/overnight_bench.py deepseek-r1:14b

For a cloud model, point `bench_one_json.py` at an `LLMConfig` with the relevant
provider. Results append to the same JSONL keyed by `model`, and the charts
already filter on that field.
